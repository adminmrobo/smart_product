분류의 비유 — 의사결정 나무

비유: 갈림길데이터: 판재 1,000개

일상으로 치면

"비가 오나? → 우산. 아니면 기온이 30도 넘나? → 반팔." 갈림길을 따라가면 마지막에 하나의 결론에 닿는다.

회귀의 비유 — 안전벨트와 마모

04.4

결정 경계 — 정상과 이상을 가르는 선

개념: 결정 경계데이터: 거칠기 × 초음파

왜 이 방법을 쓰나

측정값 두 개(거칠기, 초음파)로 판재 1,000개를 찍으면 정상 점과 불량 점이 섞여 있습니다.

변수 하나만 보고 자르면 다른 변수로만 드러나는 불량을 놓칩니다. 너무 복잡하게 그으면 우연까지 외웁니다.

결정 경계는 평면을 둘로 가르는 선입니다. 단순한 선은 설명이 쉽고, 복잡한 선은 데이터에 더 붙습니다. 모양은 데이터가 정합니다.

쉽게 말하면 — 운동장에 분필로 선을 긋고 "이 선 밖은 불량"이라고 정하는 일.

아래 산점도는 실제 판재 1,000개입니다. 두 기준선을 움직여 정상 영역(왼쪽 아래 사각형)을 정해 보세요. 표는 네 가지 결과(TP·TN·FP·FN)를 바로 셉니다.

04.8

분류 프롬프트 카드 — 역할 · 출력 형식 · few-shot

카드: 분류QWEN: JSON 한 줄

2주차 5원칙이 카드 세 장으로 바뀝니다. ① 시스템 역할 — 품질 분석가 ② 출력 형식 — JSON 한 줄(machine_failure, predicted_failure_mode, confidence, rationale) ③ few-shot 예시 2개 — 정상 하나, 이상 하나.

JSON으로 받는 이유는 5주차 앱이 그 결과를 사람 손 없이 카드로 옮기기 위해서입니다. 출력을 사람이 다시 정리하고 있다면 형식 카드가 약한 것입니다.

당신은 같은 품질 분석가로 일한다. 입력은 한 부품의 다섯 환경 측정값이다. 아래 출력 형식을 따른다. [입력 — 다섯 개] - air_temp_k (공기 온도, K) - process_temp_k (공정 온도, K) - rotational_speed_rpm (회전수, rpm) - torque_nm (토크, Nm) - tool_wear_min (도구 누적 가동 시간, 분) [출력 — JSON 한 줄] {"machine_failure": 0 또는 1, "predicted_failure_mode": "twf" | "hdf" | "pwf" | "osf" | "rnf" | null, "confidence": 0.0 ~ 1.0, "rationale": "한 줄 이유 (한국어)"} rules: - machine_failure가 0이면 predicted_failure_mode는 null이다. - machine_failure가 1이면 predicted_failure_mode는 정확히 하나다. - confidence는 모델 자신의 확신 정도다 (0.0~1.0). - rationale은 한 줄, 30자 내외. [예시 01 — 정상] air 300.1 · process 309.5 · rotation 1520 · torque 36.0 · wear 130 → {"machine_failure": 0, "predicted_failure_mode": null, "confidence": 0.91, "rationale": "다섯 입력 모두 정상 부근"} [예시 02 — 이상 (도구 마모)] air 300.4 · process 310.0 · rotation 1530 · torque 39.0 · wear 232 → {"machine_failure": 1, "predicted_failure_mode": "twf", "confidence": 0.86, "rationale": "마모 232분 — 임계 초과"}
